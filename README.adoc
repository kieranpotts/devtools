= Devtools

This repository contains configurations for some of my development tools including Visual Studio Code and Windows Terminal. It also contains Windows ports of various Unix looks like `make` and `wget`, which I use often.

My devtools are for installation directly on Windows. I also maintain link:https://github.com/kieranpotts/dotfiles[dotfiles] that capture further devtools configurations for UNIX-like environments. I install my dotfiles in guest VMs like WSL, emulators like Git Bash, and remote dev VMs.

== Documentation

=== Requirements

Configurations are included for the following programs, all of which are OPTIONAL:

* link:https://www.sublimemerge.com/[Sublime Merge]
* link:https://code.visualstudio.com/[Visual Studio Code]
* link:https://github.com/microsoft/terminal[Windows Terminal]

=== Installation


Steps to install and update these devtools on your Windows machine.

==== 1. Fork and clone

Fork this repository to your own GitHub account, then clone the upstream repository to any location on your local machine.

[source]
----
git clone git@github.com:<user_or_org>/devtools.git
----

==== 2. Install the fonts

The configurations for VS Code and Windows Terminal depend on the following fonts being installed locally:

* Hack
* Hack Nerd Font

TrueType formats of both fonts are included in the `./vendor/fonts` directory and need to be installed manually.

[NOTE]
======
Hack is a programming font. It adds special ligatures that merge multiple consecutive characters into a single composite glyph, for example `>=` is presented as `≥` and `!=` as `≠`, improving readability without changing the code. Hack NF (Nerd Font) is a version of the same font extended with additional glyphs that are used to create visual effects like icons and rounded corners in a shell's prompt line.
======

==== 3. Create symlinks to the configuration files

Configuration files are included for various development tools, including VS Code and Windows Terminal, for easy portability between machines. To use these configuration, you will need to create symlinks to them, from the locations the target programs expect them to be.

Run Windows Powershell in administrator mode and execute the following commands, changing the filesystem paths as required.

.Sublime Merge
[source]
----
New-Item -ItemType SymbolicLink -Path "C:\Users\[User]\AppData\Roaming\Sublime Merge\Packages\User\Preferences.sublime-settings" -Target "C:\path\to\devtools\etc\sublime-merge\Preferences.sublime-settings" -Force
----

.VS Code / VS Codium
[source]
----
New-Item -ItemType SymbolicLink -Path "C:\Users\[User]\AppData\Roaming\[Code|VSCodium]\User\settings.json" -Target "C:\path\to\devtools\etc\vscode\settings.json" -Force

New-Item -ItemType SymbolicLink -Path "C:\Users\[User]\AppData\Roaming\[Code|VSCodium]\User\keybindings.json" -Target "C:\path\to\devtools\etc\vscode\keybindings.json" -Force

New-Item -ItemType SymbolicLink -Path "C:\Users\[User]\AppData\Roaming\[Code|VSCodium]\User\snippets\global.code-snippets" -Target "C:\path\to\devtools\etc\vscode\global.code-snippets" -Force
----

.Windows Terminal
[source]
----
New-Item -ItemType SymbolicLink -Path "C:\Users\[User]\AppData\Local\Packages\Microsoft.WindowsTerminal_[hash]\LocalState\settings.json" -Target "C:\path\to\devtools\etc\wt\settings.json" -Force
----

==== 4. Add the `bin` directory to your PATH environment variable

Windows binaries for various programs are bundled in the `bin` directory of this repository. These programs can be installed on your Windows machine simply by adding this repository's `bin` directory to your system's `PATH` environment variable.

[NOTE]
======
The `delta`, `lazygit`, `oh-my-posh` binaries are required for my link:https://github.com/kieranpotts/dotfiles[dotfiles] configuration to work in Git Bash for Windows. For WSL2 and other Unix environments, the equivalent packages can be installed using my link:https://github.com/kieranpotts/bootstrap[bootstrap] script.
======

==== 5. Sync VS Code settings with GitHub Codespaces

Optionally, you can use GitHub Settings Sync to keep your local VS Code settings in sync with your GitHub Codespaces. Go to your https://github.com/settings/codespaces[GitHub Codespaces options] and enable the following option:

image::./_/github-enable-settings-sync.png[]

You will need to login to VS Code using your GitHub account, and enable Settings Sync in your user settings. With all of these steps completed, your GitHub Codespaces will automatically load your local VS Code settings, ensuring a consistent user experience between cloud and local instances of VS Code.

=== Maintenance

NOTE: The following documentation is for the project maintainers.

Fresh Windows binaries can be downloaded from the following links. The binaries bundled in this repository are for the x86-64 architecture, also known as x86_64, x64, or amd64, and compatible with the 64-bit CPU architecture used in Intel and AMD processors.

* link:https://github.com/dandavison/delta/releases[*delta*]: Look for `delta-<version>-x86_64-pc-windows-msvc.zip`

* link:https://github.com/mgdm/htmlq/releases[*htmlq*]: Look for the latest `htmlq-x86_64-windows.zip` release.

* link:https://github.com/jqlang/jq/releases[*jq*]: Look for the latest `jq-win64.exe` release.

* link:https://github.com/jesseduffield/lazygit/releases[*lazygit*]: Extract from `lazygit_<version>_Windows_x86_64.zip`.

* link:https://sourceforge.net/projects/ezwinports/files/[*make*]: Search for the latest `without-guile-w32-bin` and extract the `make.exe` file from the archive.

* link:https://github.com/coreybutler/nvm-windows/releases/[*nvm (Node Version Manager) for Windows*]: Download the latest `nvm-noinstall.zip` archive and extract the `nvm.exe` file.

* link:https://github.com/JanDeDobbeleer/oh-my-posh/releases[*oh-my-posh*]: Download the `posh-windows-arm64.exe` file and rename it to `oh-my-posh.exe`.

* link:https://eternallybored.org/misc/wget/[*wget*]: Download the latest x64 `.exe` file.

* link:https://www.xpdfreader.com/download.html[*Xpdf*]: Download the Windows Xpdf command line tool, extract, and copy the contents of the `bin64` directory.

*NeoVim* is not available as a standalone binary. It MUST be link:https://github.com/neovim/neovim/blob/master/INSTALL.md[installed using a package manager] like Winget or Chocolatey, or the Windows installer package available from the project's link:https://github.com/neovim/neovim/releases[releases page].
